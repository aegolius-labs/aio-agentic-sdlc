# aio-agentic-sdlc

## What this is

A **framework**, not a tool or a platform. It inverts control: agents working in a
repository that adopts it must conform to its architecture — the dual-DAG model, the
authority ladder, and the approval gates below. A tool does one job when called; this
prescribes how the whole SDLC is structured.

It is the long-term end product of Aegolius Labs. `agentic-backlog-kit` and
`agentic-qa-kit` were extracted from concepts here so that a developer could use a fast,
dependency-free slice without adopting the whole framework. They federate with it; they
are not part of it. See `doc/authority-model.md`.

## The North Star

Read `doc/VISION.md` before any architectural change. The core claim:

> The Backlog is not a list of user-created tasks. The Backlog is mathematically defined
> as the **Diff** between the Intention DAG and the Reality DAG.

- **Intention DAG** (`.aio-agentic-sdlc/intention-dag.yaml`) — what the software *should*
  be. Durable, version-controlled, human-approved.
- **Reality DAG** (`.aio-agentic-sdlc/reality-dag.yaml`) — what the software *is*.
  Regenerated by statically analyzing the codebase. Evidence, never intent.
- **The diff** — what must happen to make Reality satisfy Intention. This is the work.

The intended loop: a human states a want → the Intake agent turns it into Intention DAG
nodes in the right place in the graph → a new diff is computed against Reality → work
items are cut from that diff → an implementing agent knows exactly what is missing.

Both DAGs must speak the same ontology, which is why the Reality generator is in-house
rather than a third-party code-graph tool.

## The authority ladder

`doc/authority-model.md` is normative. Authority flows strictly downward; a lower layer
may never select, override, or silently edit a higher one.

| Layer | Artifact | Kind of truth |
| --- | --- | --- |
| 1 | `intention-dag.yaml` | What the software **should** be |
| 2 | `reality-dag.yaml` | What it **is** — observation, not intent |
| 3 | `backlog.json` | The **work** — the evidence-gated diff of 1 and 2 |
| 4 | GitHub, via `agentic-backlog-kit` | A **projection** of layer 3. Never authoritative |
| 5 | `.agentic-qa/` ledger, via `agentic-qa-kit` | **Evidence about reality** |

> **The governing rule: downstream state flows back as evidence, never as intent.**

A closed issue, a green CI run, a confirmed QA finding — all are observations. They may
inform layers 2 and 3. They may **never** edit layer 1. Changing what the software is
supposed to be is always an explicit, approval-gated Intent IR transition made by this
framework's own tooling.

## Intent IR and the approval gate

`doc/adr/0002-intent-ir-v1.md` is the contract. An Intention node may carry an `intent`
payload recording provenance, assumptions, ambiguities, bounded confidence, acceptance
criteria with required evidence, a monotonic revision history, and an explicit approval
state (`draft` / `review_required` / `approved` / `rejected`).

Unknown fields fail validation. Revisions start at 1 and increase strictly. Approved
intent requires both an approver and a timestamp.

`set_intent` and `dag-tool intent set` are the only supported single-node mutation
surfaces. They lock, require the caller's expected revision, preserve history, append
exactly one revision, and atomically replace the file. Review and validation commands
(`intent-summary`, `validate-intent`) never mutate.

## Mapping: what approval does and does not mean

Reconciliation can match an Intention node to a Reality symbol by normalized name and
structural type. **That narrows the search; it does not prove they share a
responsibility.** See `doc/mapping-review.md`.

Approving a mapping means exactly one thing: *this source symbol is the canonical
implementation identity for this Intention node.* It does **not** approve the Intent IR,
close ambiguities, or mark any acceptance criterion satisfied. Related tests are
discovery aids, not behavioral proof.

Approved mappings are recorded as `# aio-sdlc-mapping-approval:` receipts in the source
file, alongside `# aio-sdlc-node:` GUID markers. Always run the read-only
`mapping review` before writing an identity marker.

## Common misreadings — check yourself against these

These are real errors made by agents working on this repository.

1. **"The Intention DAG contains things that don't exist — that's pollution."**
   Wrong, and backwards. Intention nodes without a Reality counterpart are the entire
   point; they are the signal the diff exists to surface. An Intention DAG that mirrored
   Reality would have nothing to say.

2. **"Intent must be backed by a prior document to be legitimate."**
   No. Provenance is an audit trail of *who asserted this*, not a justification
   requirement. `ProvenanceType` includes `human_statement` and `conversation` precisely
   because a person simply wanting something is valid intent.

3. **"Nodes at `review_required` with 0.55–0.65 confidence indicate a corrupted corpus."**
   That is specified behavior. ADR 0002: the legacy migration compiler emits *every*
   mechanically compiled payload as `review_required` with an open ambiguity. It is the
   system being honest about inference, not failing.

4. **"`responsible_agent: sdlc_cartographer` means the mapping agent authored the intent,
   so Intention was derived from Reality."**
   No. It is a plain string field stamped by whichever actor last touched the payload —
   for migrated nodes, the batch migration's actor. It is not evidence of authorship.

5. **Treating GitHub issues as the work.** They are layer 4, a projection. Work is cut
   from the layer 3 diff. Filing an observed defect as *new intent* laundries evidence
   into layer 1 and violates the governing rule.

When a conclusion implies the framework's own design is wrong, check the ADRs and the
change records under `.aio-agentic-sdlc/changes/` before asserting it. The design is
usually deliberate and documented.

| Reality nodes | 756 |

| Completed dogfood cycles | 10, under `.aio-agentic-sdlc/changes/` |

The practical bottleneck is **mapping coverage**, not intent quality. With 10 receipts
against 756 Reality nodes, reconciliation cannot resolve most nodes in either direction —
it cannot confirm what is done, so it cannot isolate what is missing.

A 1:12 Intention-to-Reality node ratio is expected, not a defect: Intention nodes are
architectural components, Reality nodes are individual symbols.

## State contract

- `intention-dag.yaml` — durable, committed, version-controlled intent.
- `reality-dag.yaml` — regenerable observation; committed but never hand-edited.
- `backlog.json` — gitignored local execution queue derived from the diff.
- `state-audit.jsonl` — gitignored append-only transaction journal.
- `config.json` — project-local hierarchy and validation configuration.
- `changes/`, `specs/`, `inbox/`, `archive/`, `research-spikes/` — framework artifacts.
  `changes/` **is** committed: it is this project's own dogfooding evidence trail, and
  large generated JSON there is expected, not accidental.

Backlog writes use a versioned envelope with a monotonic `revision`, a cross-process
`filelock`, and a JSONL journal; incomplete transactions are reconciled from the file
hash on next read and an unknown hash fails closed (ADR 0001). Never write these files
directly — go through the tooling so locking, revision checks, and audit records hold.

## Conventions

Conventional Commits. Work on a feature branch, push, open a PR. A release-bearing type
on `main` triggers automation that computes a version, tags, and publishes a GitHub
Release — `feat:` cuts a minor version, `docs:` and `chore:` cut nothing. Choose the
squash-merge commit type deliberately.

`main` is protected by a ruleset requiring one approving review; organization admins
carry an explicit always-on bypass.
